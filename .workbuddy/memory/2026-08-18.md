## Pollinations 额度机制（实测澄清，纠正之前错误说法）
- 钱包制：账号有 Wallet，余额分 PAID / QUEST / TOTAL pollen。免费 pollen 来自 **Quests（任务中心）领取**，不是自动每日送。
- 实测（2026-08-18）：用户做完一个 onboarding quest，钱包 QUEST 到账 **0.25 pollen**（TOTAL=0.25）；但用 key 调 `/v1/chat/completions` 仍 402，报错 `this key has 0.0000 pollen`。
- 关键机制：**钱包余额与 key 自身 budget 是分开的**。创建 key 时 Budget 选 `Unlimited` ≠ 从钱包扣费，而是「上限不封顶但 key 独立预算初始为 0」，请求查 key 自己余额=0→402。
- 正确做法：创建 key 时 Budget **填具体数字**（如 0.25），或在 key 详情里「分配 pollen / 关联钱包」；否则 key 用不了钱包余额。
- 端点：认证用户走 `/v1/chat/completions` 要 pollen（legacy 端点正废弃，提示迁移 enter.pollinations.ai）；**经典 `text.pollinations.ai` 接口实测也不稳定**：hello 偶尔 200，普通短句/中文/工具型 prompt 返回 402，中文关键词还触发 400 Bad Request。
- 代码现状：`tw-feedback-ai.js` 读 `localStorage.twt_ai_api_key`；留空=匿名，填了=用该 key（需 key 自身有 budget）。
- 之前「每日免费 pollen / 每周 1.5」说法过时——当前实测注册用户无自动赠送，仅 Quests 任务领（用户领到 0.25）。
- 安全：那把 `sk_GBXJ…l15H` 已泄露在对话中，建议 revoke 并重新生成。
- 结论：当前 Pollinations 没有可用的免费稳定路径；要继续 LLM 审核需给 key 分配 budget 或充值，或改用纯前端本地规则过滤。

## AI 审核后端从 Pollinations 迁移到 SiliconFlow（硅基流动）
- 背景：Pollinations 国内无免费稳定路径（402/400）。用户怕被扣费，要求确认「免费 + 不扣费」。
- 选型：SiliconFlow（api.siliconflow.cn，国内可访问、OpenAI 兼容、新用户送 14 元≈2000万 token、注册不绑信用卡）。
- 计费事实（已 WebSearch 核实 2026-08-18）：预付费；调用按 token 从「余额」扣，优先扣赠送额度；**余额用完返回 402，绝不自动从银行卡/支付宝扣钱**（充值须手动）。免费模型 15 个价格 0 元（如 Qwen/Qwen2.5-7B-Instruct、Qwen/Qwen3-8B、THUDM/GLM-4-9B-0414），免费档限速 50 次/天（未充值）。DeepSeek-V3 付费但极便宜：输入¥2/百万、输出¥8/百万，单次审核≈¥0.0008。
- 用户最终选择：**免费模型（0 元）+ 发 key 实测**。
- 改动：
  - `webpack.config.js` proxy target → `https://api.siliconflow.cn`（pathRewrite 去 `/tw-ai-proxy`）。
  - `src/lib/tw-feedback-ai.js`：`PROXY_BASE='/tw-ai-proxy/v1/chat/completions'`；`MODEL='Qwen/Qwen2.5-7B-Instruct'`（注释保留换 DeepSeek-V3 的说明）；`Authorization: Bearer <localStorage.twt_ai_api_key>`；fail-closed 解析与重试保留。
  - `src/components/tw-settings-modal/settings-modal.jsx`：设置项文案改指 SiliconFlow（API Key 仅存本机）。
- 实测（用户提供的 key，走 `localhost:8601/tw-ai-proxy`）：HTTP 200，免费模型返回「通过/不通过」；用生产完整审核提示词测 6 例（功能建议/感谢/求助→通过；辱骂/广告/灌水→不通过）**全部判对**。证明 key 有效、代理通、0 元、判定准。
- 注意：用简化提示词时该 7B 模型会误判（如正常建议判不通过），必须用语雀完整 MODERATION_SYSTEM。免费档 50 次/天限速若不够，换回 DeepSeek-V3。

## npm run build 报错排查（2026-08-18）
- 现象：用户报告「npm报错」。逐步排查：`npx webpack` 编译通过（EXIT=0，bundle 正常）；dev server（`npm start`）正常、8601 返回 200；eslint 仅 style 错误（max-len/空格/JSDoc），webpack 未挂 eslint-loader，不影响 start/build。
- 根因：`npm run build` 在 `clean` 步骤死掉——`rimraf ./build` 被 WorkBuddy 的 `genie-safe-delete` 安全删除 shim 拦截，试图把文件移入回收站，回收站操作报 `Some operations were aborted` 而抛错。已验证**所有删除**（rimraf、fs.rmSync 都）被该 shim 拦截并失败。属环境问题，非代码 bug。
- 修复：`package.json` 的 `clean` 脚本改为 best-effort：`rimraf ./build || true && mkdirp build || true && rimraf ./dist || true && mkdirp dist || true`。改后 `npm run build` EXIT=0，产出 build/editor.html、build/index.html。
- 注意：若用户 `npm start` 报 EADDRINUSE，是 8601 端口已被旧 dev server 占用（非代码错），kill 旧的再 start 或只刷新页面即可。

## 反馈区「审核服务暂不可用」根因 + 直连修复（2026-08-18 续）
- 现象：用户问"审核服务不可用是怎么个事情"，要项目连上新 AI 审核。
- 机制：`feedback-modal.jsx` onSubmit 调 `moderateFeedback(text)`，其 `.catch` 一律 flash `fReviewUnavailable`（fail-closed：审核调不通就拦截发布，避免漏审）。触发条件 = fetch 失败（无 key→401 / 限速→429 / 网络错 / 404）。
- 根因（真 bug）：`tw-feedback-ai.js` 旧版 `PROXY_BASE='/tw-ai-proxy/v1/chat/completions'`，该路径**只在 `npm start` 的 webpack-dev-server 代理下存在**；构建后静态部署没有代理，fetch 必然 404 → 永远"审核服务暂不可用"。也即 AI 审核在非 dev 环境根本连不上。
- 验证：SiliconFlow `OPTIONS` 预检返回 `Access-Control-Allow-Origin: *`，浏览器可**直接跨域调用**，dev 与构建版都能连。
- 修复：
  - `tw-feedback-ai.js`：`PROXY_BASE` → `API_BASE='https://api.siliconflow.cn/v1/chat/completions'`，`fetch(API_BASE,...)` 直连；更新头部注释（直连、CORS 已放行）。
  - `webpack.config.js`：删除已无用的 `/tw-ai-proxy` proxy 块（死配置）。
  - grep 确认 src/webpack 已无 `tw-ai-proxy`/`PROXY_BASE` 残留；babel OK。
  - 直连实测（带用户 key）HTTP 200，返回「通过/不通过」。
- 前置条件（务必提醒用户）：key 须填进 Settings→TwT 服务（`localStorage.twt_ai_api_key`）；留空则 401 仍报"服务不可用"。免费模型 `Qwen/Qwen2.5-7B-Instruct` 限速 50 次/天，超限 429 也会触发该提示。

- 用户反馈：SiliconFlow 控制台「一次请求记录都没有」「你是不是根本没请求」。
