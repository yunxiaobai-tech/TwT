## 头像系统全链路修复

### 问题诊断
用户重跑 `tw-db-schema.sql` 后，`select=device_id` 可正常读取（HTTP 200），但 `select=avatar_url` 报 `42501 permission denied`。

**根本原因**：原 SQL 先 `REVOKE SELECT ON public.usernames`（整表撤销），再 `GRANT SELECT (列列表)`（列级授权）。在 Postgres 中，列级 GRANT 行为与 RLS 组合时可能出现授权不一致。

### 修复方案
- 创建独立修复 SQL：`sql-fix-avatar-grant.sql`
- 策略改为：`REVOKE ALL` → `GRANT SELECT (公开列+avatar_url)` → `REVOKE SELECT (敏感列)` 三步走
- 幂等设计，可重复执行，不影响现有数据
- 同时修复了 `feedback.owner_secret` 和 `email_sessions.password_hash` 的权限遗漏
