## 修复：Invalid extension URL 报错
- 用户运行报 `Error: Invalid extension URL: /extensions/audio-codec.js`。根因不是没部署，而是两点：
  1. scratch-vm `_isValidExtensionURL`（`node_modules/scratch-vm/.../extension-manager.js:185`）用 `new URL()` 解析，**相对路径**会抛异常被拒，必须 `http(s):/data:/file:` 绝对地址。
  2. TwT 安全管理器白名单 `isTrustedExtension`（`src/containers/tw-security-manager.jsx:26`）只信任 turbowarp.org / netlify.app / `http://localhost:8000/`；devServer 实际端口是 **8601**（`webpack.config.js:40`），同源 8601 不在白名单会被拦。
- 修正：
  1. `index.jsx:442` 改为 `extensionURL: \`${window.location.origin}/extensions/audio-codec.js\``（同源绝对地址，自动适配端口/域名）。
  2. `tw-security-manager.jsx` 的 `isTrustedExtension` 增加 `url.startsWith(\`${window.location.origin}/\`)`（同源即信任，非沙箱加载）。
- 验证：`rewriteExtensionURL` 基类（`node_modules/scratch-vm/.../tw-security-manager.js:58`）原样返回 URL，无 trampoline 改写；historyApiFallback 规则不匹配 `/extensions/*.js`，静态文件正常返回。
- 结论：改两处字符串即可，易退回、危害低。

## 修复：AI 调用返回 402 Payment Required
- 用户报「无法访问402」。实测复现：经 dev 代理 `/tw-ai-proxy` → `https://text.pollinations.ai/v1/chat/completions`（model `openai`）。
- 根因（非代码 bug、非模型错）：**Pollinations 匿名通道按 IP 有 budget 限制**，用几次就返回 `402 Payment Required: API key budget too low. This request requires an API key with sufficient budget.` 官方 deprecation notice 也承认「匿名请求本应不受影响」但实测匿名会耗尽。最小请求最初能 200（匿名），多次调用后本机 IP 预算耗尽 → 任何请求统一 402。其它模型（mistral/llama/gpt-4o-mini 等）在 pollinations 上返回 404，所以 `openai` 是唯一可用模型。
- 修法（用户确认「自填 Pollinations token」）：
  1. `src/lib/tw-ai-addon-store.js` 新增 `tw_ai_token` 持久化（get/set/clear，仅本地、不进 bundle）。
  2. `src/lib/tw-ai-addon.js`：`callProxy` 读取 token，有则加 `Authorization: Bearer <token>` 头；402 时抛**友好中文报错**（提示去 enter.pollinations.ai 取免费 token）。
  3. `src/components/tw-ai-addon-modal/ai-addon-modal.jsx` + `.css`：弹窗顶部新增可选「Pollinations API Token」输入框（password 类型，存 localStorage，含获取链接提示），匿名作兜底。
  4. dev 代理（`webpack.config.js` 的 `/tw-ai-proxy`）`onProxyReq` 只剥离 origin/referer，**默认原样转发 Authorization**，无需改代理即可让 key 到达上游。
- 易退回：✅（token 走 localStorage，删即回退匿名）；把握度：✅高（标准 Bearer 头）；危害：🟢低（key 仅存本地/服务端代理侧，不进客户端 bundle，且是用户自己的 key）。
- 验证：dev server 重编译 `Compiled successfully.`；bundle grep 命中 `enter.pollinations.ai`×3、`Bearer`×2、`匿名额度已耗尽`×1、`tw_ai_token`×1。
- 用户侧操作：去 `enter.pollinations.ai` 免费注册拿 token，粘进弹窗输入框，即可稳定调用，不再 402。

- 需求：隐藏「查看作品/首页」(playerOnly 且非全屏) 右侧浏览器原生滚动条，但保留滚动能力（滚轮/触摸/键盘）。
- 根因：`render-interface.jsx` 的 `.container` 为 `position:absolute` 无高度限制，内容超出视口时由 `html/body`(窗口) 滚动，出现原生滚动条。
- 改动：
  - `src/playground/render-interface.jsx`：`Interface` 类新增 `componentDidMount/componentDidUpdate/componentWillUnmount` + `updatePlayerHomeClass()`，按 `isPlayerOnly && !isFullScreen` 给 `document.documentElement` 与 `document.body` 同时切换稳定类 `twt-player-home`。
  - `src/playground/interface.css`：用 `:global(html.twt-player-home), :global(body.twt-player-home)` 加 `scrollbar-width:none; -ms-overflow-style:none;` 及 `::-webkit-scrollbar{display:none}` 隐藏滚动条（滚动仍可用）。`:global()` 穿透 CSS Modules 哈希。
  - 仅作用于首页/查看作品页，编辑器全高布局不受影响。
- **关键坑（第一版没生效的原因）**：视口滚动条由 `<html>`(documentElement) 控制，不只 `<body>`。第一版只把类加在 body 上，于是 `body.twt-player-home` 只影响 body 自身滚动条，窗口滚动条照旧显示。修正为类同时加到 `document.documentElement`（以及 body 兜底）。headless `--dump-dom` 确认 `<html class="twt-player-home">` 已生效。
- 验证：`curl` bundle `player.js` 含 `twt-player-home` 与 scrollbar 规则；headless `--dump-dom` 确认 `<html class="twt-player-home">` 与 `<body class="twt-player-home">`。
